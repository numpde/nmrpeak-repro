CPU/GPU benchmark implementation and ProArt evidence (2026-10-15)
===============================================================

Source and interface
--------------------

Qualified source: 4331147244aaa9cab5356b8dc864065950c3e592.
Implementation commits: 7254f5b, 53709ff, 371fc8e, a3a9ed3, a4c7ba8, 4331147.
All were pushed to origin/main before the full comparison.

Use make benchmark/image/build, then make benchmark. See docs/benchmark.md for
selection, measurements, resource grants, failure behavior, and limitations.
The Python harness compares HF and CHF on the current CPU stack, a common
CPU/CUDA image on CPU, and each selected GPU by full UUID. Production runner
wrappers remain explicitly CPU. This work did not restart production services
or submit API Jobs.

Cache reuse and dependency limits
--------------------------------

All three NMRPeak image Dockerfiles now use the builder-wide UV cache mount
/root/.cache/uv with sharing=locked and no repository/lane-specific ID. Hash
verification remains specific to each image's lock. Other repositories can
reuse the same mount on the same builder; sibling repositories were not edited.

On ProArt, the previously populated NMRPeak CPU and CUDA caches were preserved
as read-only donors for a one-off migration into the initially empty shared
cache. Fresh CPU and CUDA environments were then installed with network disabled,
UV offline mode, and required hashes; pip check and exact PyTorch version imports
passed. Evidence and exit 0:

  /tmp/nmrpeak-uv-shared-cache-20261015/proof.log
  /tmp/nmrpeak-uv-shared-cache-20261015/proof.exit

The subsequent three-image rebuild completed with zero package Downloading
events in /tmp/nmrpeak-benchmark-qualification-4331147/build.log. Interrupted
downloads from the earlier canceled build were not reusable completed artifacts.
The cache is an optimization; independent image environments and differing CPU/
CUDA wheels are still required. Builder garbage collection can remove artifacts.

The common image uses the committed hash-locked PyTorch 2.10.0+cu128 stack.
The 61-package advisory review found known issues documented in docs/benchmark.md;
this is not an advisory-free image. It uses trusted committed code, verified
local checkpoints, fixed configuration, and synthetic inputs. The production
dependency lock was not changed.
